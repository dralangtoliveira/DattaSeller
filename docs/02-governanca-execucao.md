## Regra de entrega

Um card não deve ser encerrado apenas por atividade realizada. A conclusão precisa corresponder a um valor entregue verificável, compatível com a propriedade **Valor entregue** e com suas dependências.

Para alterações técnicas, a evidência preferencial deve ser código/configuração versionada, teste e resultado observável. Para negócio, deve existir documento, catálogo, regra, fluxo ou decisão concreta. Para integrações, deve existir fluxo executável e validado. Para validação, deve existir teste com resultado e critério de aceite.

## Relação Notion x GitHub

- **Notion:** planejamento, cards, dependências, status, prioridade, decisões operacionais e acompanhamento.
- **GitHub:** documentação versionada, arquitetura, fluxos, código, configuração, testes e evidências técnicas.

O nome oficial do projeto passa a ser **DattaSeller**. Referências históricas a “Central Comercial Datta” devem ser entendidas como o nome anterior do mesmo projeto e devem ser substituídas progressivamente nos artefatos ativos.
